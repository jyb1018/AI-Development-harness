# 모델 업데이트와 하네스 변경 시점

## 알림 조건

업데이트 이름이나 웹페이지 해시가 바뀌었다는 사실만으로 수정하지 않습니다.
공식 문서의 instruction/skill loading, persistence/compaction, tool/approval,
subagent, effort 또는 API 호환성 변경이 이 하네스에 영향을 줄 때 **평가 필요**를 알립니다.
실제 regression 증거 또는 깨진 인터페이스가 확인되면 **수정 권고**로 구분합니다.
가격·마케팅·일반 ChatGPT UI 변화만으로 기본 규칙을 개정하지 않습니다.

## 예약 기능에서 사용할 지침

공식 OpenAI 모델 발표·Model guidance·Codex/ChatGPT release notes를 확인하고,
`jyb1018/AI-Development-harness`의 현재 default branch와 열린 v2 PR의 핵심/프로필/스킬을
읽어 영향 범위를 비교한다. 읽을 수 없으면 마지막 확인 revision과 한계를 밝힌다.
단순 신모델 소식이 아니라 이 하네스의 수정 또는 재평가가 필요한 새 변화만 한국어로 알린다.
알림에는 발표일과 적용일, 공식 근거, 영향받는 파일/규칙, 우선순위, 최소 검증 과제를 담는다.
같은 근거와 revision 조합은 중복 알리지 않는다. 의미 있는 변화가 없으면 알리지 않는다.
문서 접근 실패를 모델 변경으로 해석하지 말고, 반복되어 감시가 불가능해지면 별도로 알린다.
저장소·설정·모델을 자동 수정하거나 유료 평가를 실행하지 않는다.

## 범용 패키지와 개인 예약의 경계

이 지침은 예약을 설정할 때 사용하는 명세입니다. 파일을 설치해도 예약은 생성되지 않습니다.
예약은 계정에서 별도 생성하며 이메일/푸시 전달은 해당 계정의 알림 설정에 따릅니다.
v1의 `model-watch.yml`과 fingerprint script는 2.0에 포함하지 않습니다.
문서 접근 오류, 부분 응답, 새로운 문구를 실제 행동 회귀와 혼동하지 않기 위해서입니다.
기존 저장소의 예약 workflow를 제거하려면 그 저장소에서 별도 승인/변경을 해야 합니다.

## 변경 결정

`evals/README.md`의 비교 방식으로 현재/후보 규칙을 평가합니다.
호스트만 바뀐 경우 모델을 탓하지 말고 instruction load와 tools를 먼저 확인합니다.
문제가 없으면 **하네스 변경 없음**도 유효한 결론입니다.
문제가 있으면 한 규칙 또는 한 스킬만 수정하고 회귀를 다시 확인합니다.
안전·권한 경계가 약해지거나 실제 acceptance 성공률이 떨어지면 이전 revision으로 돌아갑니다.
