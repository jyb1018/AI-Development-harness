# v1 또는 무거운 하네스에서 이관

v1을 덮어쓰기보다 기존 지침과 설치된 훅을 먼저 확인하십시오.
2.0 설치기는 이전의 `ponytail`, `thin-process` 등 일반 이름 디렉터리를 삭제하지 않습니다.
`uh-*`와 이전 규칙을 동시에 강제 로드하면 과잉 지시가 다시 생길 수 있습니다.

| 이전 방식 | 2.0 방식 |
|---|---|
| 모든 작업에 acceptance 문장·문서 의무 | 사소한 수정에는 생략, 실질 작업에 관찰 가능한 결과 |
| 테스트 불변이라는 절대 규칙 | 성공을 위한 약화 금지; 승인된 동작과 충돌하는 테스트는 근거와 함께 수정 |
| 작은 커밋마다 종료/스레드 교체 | 요청 전체가 끝날 때까지 진행; 실제 handoff 시만 짧은 상태 보존 |
| 독립 리뷰를 못 띄우면 모든 구현 중단 | 안전한 로컬 작업은 수행; 위험한 release만 미검증 상태로 보류 |
| Development라는 이유로 자동 활성화 | 명시적으로 선택한 격리 테스트 경로 활성; 외부 효과는 별도 범위 확인 |
| 모든 API에 하나의 스위치만 허용 | 실제 보안 경계는 보존; 숨은 no-op gate만 제거 |
| 실제 요청 한 번 성공 = 모든 연동 완료 | read/write/시간/권위가 다른 경로는 별도 시나리오 필요 |
| 해시 변경 때마다 수정 이슈 | 공식 변경의 영향 분석 후 필요한 알림/평가 |
| 모든 스킬 매번 로드 | core 하나 + 관련 skill만 |

기존 도메인 invariants, 인증/권한, migration safeguards, 실제 acceptance test는 유지합니다.
이전 task 기록은 역사 자료이지 새로운 에이전트의 현재 지시가 아닙니다.
전역 설정·설치된 플러그인 제거는 사용자 승인 후 별도로 진행하십시오.

첫 이관은 작은 실제 버그와 통합 경로 하나로 확인하고 기존 방식과 결과를 비교합니다.
규칙 수가 줄었다는 이유로 품질이 개선됐다고 결론 내리지 마십시오.
